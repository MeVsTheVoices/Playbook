K3s Distribution

This section opens automatically for k3s images and defaults to a valid config block used by the later bootstrap step.

Most users only need the server endpoint here; it tells K3s where the control-plane API lives.

Warning: keep this off for now. The baseline adds --secrets-encryption, but the current cluster runs with encryption disabled, so joining control-plane nodes with it on will fail or crash-loop.

Whole number from 1 to 110. Blank uses the board default: 20 on a Pi 3B+ (it cannot carry 110), the K3s default of 110 on a Pi 5 or Pi 4.

{% if k3s_version_default %}Blank installs {{ k3s_version_default }}, the K3s on this machine, so a new node is never newer than the servers.{% else %}K3s is not installed on this machine, so blank installs the current stable release.{% endif %} Enter another version such as v1.36.4+k3s1 to pin it, or 'none' to follow the stable channel.

K3s says SD cards and eMMC cannot handle etcd's write load. Without this, a control-plane node refuses to install K3s on first boot if its root is an SD card. Boot control-plane Pis from an SSD.

'none' also disables Traefik. ingress-nginx is not offered: the Kubernetes project retired it in March 2026 (no security fixes). The options below are cluster-wide: the ones marked 'must match' have to be identical on every K3s server, including the NucBox. The Pi 5 and Pi 4 start with all of them off so they match the NucBox as-is; the Pi 3B+ starts with the lightweight set on.
