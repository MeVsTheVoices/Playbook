Summary

Monitor Guidance

This page is strongest when read top-down: fleet state first, config coverage second, then execution and hardware details, with manual overrides at the bottom.

Reading order

What is fresh?

Use Hardware Fresh, Last HW Check, and the provision outcome section to decide whether the page reflects the current node state or stale callback history.

What is assigned?

Use the cloud-init coverage section to identify nodes carrying no optional settings, and to see which option IDs are actually in use across the fleet.

What needs action?

Use Live Node Checks to trigger fresh callbacks, then use Hardware Status and the report link to inspect the exact node facts that came back.
