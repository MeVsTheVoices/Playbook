# Servarr

This wrapper pins Kubito's public Servarr chart. Settings in the values editor
are nested under `servarr:`. The bundled snapshot also includes Playbook's
qBittorrent VPN guard and the reconstructed Kubby settings.

For a new installation, review upstream chart defaults, storage, ingress and
application security before deploying. The optional VPN is off by default.
Without it qBittorrent uses the ordinary cluster network, not Mullvad.

For the existing Kubby suite, use the Kubby preset, save, then preview and
compare the entire manifest against the live cluster before deploying. It uses
`servarr` for both release and namespace, existing PVCs and Tailscale ingresses,
and enables the VPN. The existing suite was applied with kubectl, not installed
as a Helm release. Choose kubectl apply for it; this does not create a Helm
release or prune resources. Do not mix it with a Helm-managed release.

Use Refresh chart source after Playbook updates the pinned wrapper; it preserves
saved values and target without deploying. Preview and compare before applying.

The VPN requires an existing Kubernetes Secret in the target namespace with
key `client_secret`, holding a Tailscale OAuth credential with Auth Keys write
and ownership of the configured tag (Kubby uses `tag:needs-exit`). The
credential must not be put in values.
The defaults assume Kubby's pod CIDR, DNS, qBittorrent UID and Mullvad exit.
Change them to match the cluster. Cluster DNS upstream may bypass Mullvad.
The guard depends on the LinuxServer qBittorrent image running as its PUID.
Preview and independently verify both exit egress and blocked direct egress.

No automatic migration of existing resources to Helm ownership is performed.
Existing claims are not deleted by the kubectl apply method, which never uses
prune. Helm may manage and delete PVCs generated by chart values; use existing
claims and back up application data before changing installation methods.
Jellyfin, Seerr, indexers and download-client integrations still need setup.
